Hardware Build Guide

How to connect a voice brain to a real automatic sliding door controller using an ESP32 or a Raspberry Pi. This website does not connect to hardware directly.

Safety First (Read Before Wiring)

  • Do not connect any board to door motor power or mains power. Connect the microcontroller or Pi only to the low-voltage dry-contact trigger input of the commercial door controller, through a relay or an optocoupler.
  • Keep the safety sensors of the door active. Infrared beam and obstacle crush sensors must stay wired to the door controller. A voice system must not be the only safety layer.
  • Ask a licensed technician for any work on mains power.
  • Demo disclaimer: Do not claim that this demo or student prototype meets any automatic door safety standard (such as EN 16005 or ANSI/BHMA A156.10).

1. How a Real Voice Door Build Works

Every voice-controlled automatic door follows five stages. In our browser demo, stages 1 through 4 run inside Chrome or Edge and stage 5 is an animation. In a real build, you split these stages across a voice brain and a door controller board.

Stage Function In This Web Demo In a Real Hardware Build
1. Microphone Capture 16 kHz mono audio Phone or laptop microphone via Web Audio USB mic (Pi) or I2S MEMS mic like INMP441 (ESP32)
2. Speech to Text Turn spoken words into text Chrome Web Speech API (cloud or local) Vosk / Whisper.cpp on Pi, or ESP-SR wake words on ESP32
3. Voiceprint Check Verify whether the speaker matches Xenova/wavlm-base-plus-sv ONNX in browser Speaker embedding model on Pi (or laptop), not feasible on bare ESP32
4. Command or AI Decide door action (open, close, hold, lock) Mode A keyword matcher or Groq API Python script on Pi calling local rules or Groq HTTPS API
5. Door Controller Close dry-contact trigger and obey safety beam CSS sliding panel animation + FSM 5V optocoupler relay bridged across door opener wall-button terminals

2. Four Hardware Architecture Options

Option A: ESP32 Alone

An ESP32 board wires directly to an I2S microphone and a relay module, running small fixed wake-word models or sending audio over Wi-Fi.

ProsCons
Low cost (RM62.58 to RM80.00 in Malaysia), instant 1-second boot, tiny enclosure. Too little RAM (~520 KB SRAM, up to 8 MB PSRAM on ESP32-S3) for full WavLM voiceprint verification or general offline speech-to-text.

Option B: Phone or Laptop as Voice Brain + ESP32 as Door Controller

This browser demo runs the voice UI and speaker lock on a phone or laptop and sends an HTTP or MQTT open signal to an ESP32 relay over Wi-Fi.

ProsCons
Zero heavy AI code on the ESP32; reuses this web demo concept; lowest hardware cost for the door side. Requires a phone or laptop left awake near the door; depends on Wi-Fi and Chrome speech servers.

Option C: Raspberry Pi as Both Voice Brain and Door Controller

One Raspberry Pi runs microphone capture, offline or online speech recognition, voiceprint checks, and drives a GPIO relay directly.

ProsCons
Single device handles full Linux Python AI libraries, local offline speech recognition, and GPIO relay control. Higher cost (RM438.20+ for Pi 4B 4 GB), 25-to-40-second Linux boot time, and needs a clean shutdown to protect the microSD card.

Option D: Raspberry Pi as Voice Brain + ESP32 as Door Controller over Wi-Fi

The Raspberry Pi sits safely indoors running speech and speaker models, while a small ESP32 mounted inside the door header box toggles the relay over Wi-Fi.

ProsCons
Keeps expensive Pi away from door vibration and motor noise; short relay wires at the door. Two boards to power and program; Wi-Fi drop prevents triggering until reconnected.

4. Hardware Recommendation (15/11/2026)

  • Recommended Brain Board: Raspberry Pi 4 Model B (4 GB RAM). Priced at RM438.20 at Cytron Malaysia and RM490.00 (kit) at Mybotic Malaysia (checked 15/11/2026). 4 GB RAM runs local speech-to-text, speaker embeddings, and Groq API calls reliably.
  • Is a Raspberry Pi 5 needed? No. Pi 5 boards (Cytron Pi 5 series from RM202.00 entry/bundles up to RM2,020.60; 4 GB standalone listed at RM486.47 on element14 Malaysia and RM454.30 on Mouser Malaysia, checked 15/11/2026) run WavLM slightly faster, but also require active cooling and a 5V 5A USB-C adapter without changing the door outcome.
  • Why not Raspberry Pi Zero 2 W? Although very affordable at RM74.90 (Cytron Pi Zero 2 W, checked 15/11/2026), it has only 512 MB RAM, which swaps or runs out of memory when loading WavLM speaker verification alongside speech recognition. Use Zero 2 W only if all AI runs in the cloud.
  • Recommended Door Relay Controller: Cytron Robo ESP32 (RM62.58, checked 15/11/2026) paired with a 1-Channel 3V/5V OptoCoupler Relay Module (RM3.50 to RM7.00, checked 15/11/2026).

5. Step-by-Step Setup for Beginners (Options B, C, and D)

Parts List

  • Raspberry Pi 4 Model B (4 GB) + 32 GB microSD card + 5V 3A USB-C supply + USB microphone (RM14.90 at Cytron).
  • Cytron Robo ESP32 (RM62.58 at Cytron) or standard ESP32 DevKit + jumper wires.
  • 1-Channel 3V or 5V Optocoupler Relay Module (RM3.50 to RM7.00 at Cytron).
  • Existing commercial sliding door operator with a low-voltage wall-switch dry-contact terminal (labeled COM and TRIG / PUSH).

Install and Test Steps

  1. Flash Raspberry Pi OS (64-bit) onto the microSD card using Raspberry Pi Imager and plug in the USB microphone.
  2. Verify the microphone with arecord -l in the Raspberry Pi terminal, then install Python packages (pip install requests gpiozero).
  3. If using an ESP32 relay controller (Options B or D), install Arduino IDE, add the ESP32 board manager URL, plug in USB, and upload the sketch below after filling your Wi-Fi name and password.
  4. Test the relay BEFORE connecting to a door: command an open action and listen for a crisp click and continuity across COM and NO with a multimeter.
  5. Only after verifying the 500 ms pulse works cleanly on a multimeter, connect COM and NO across the door opener wall-button terminals with mains power turned off by a technician.

Sample Code: ESP32 Wi-Fi Dry-Contact Relay (Arduino C++)

Not tested on hardware. We cannot run this code on physical hardware.

#include <WiFi.h>
#include <WebServer.h>

// Replace with your local Wi-Fi network before flashing
const char* WIFI_SSID = "YOUR_WIFI_NAME";
const char* WIFI_PASS = "YOUR_WIFI_PASSWORD";
const int RELAY_PIN = 23; // Active LOW optocoupler relay

WebServer server(80);

void pulseDoorTrigger() {
  digitalWrite(RELAY_PIN, LOW);  // Close dry contact
  delay(500);                    // 500 ms simulated button press
  digitalWrite(RELAY_PIN, HIGH); // Release contact
  server.send(200, "application/json", "{\"status\":\"triggered\"}");
}

void setup() {
  pinMode(RELAY_PIN, OUTPUT);
  digitalWrite(RELAY_PIN, HIGH); // Keep relay open on boot
  Serial.begin(115200);
  WiFi.begin(WIFI_SSID, WIFI_PASS);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
  }
  Serial.println(WiFi.localIP());
  server.on("/trigger", HTTP_POST, pulseDoorTrigger);
  server.begin();
}

void loop() {
  server.handleClient();
}

Sample Code: Raspberry Pi Voice Brain and Relay Pulse (Python)

Not tested on hardware. We cannot run this code on physical hardware.

import os
import time
import requests
from gpiozero import OutputDevice

# Set GROQ_API_KEY in environment before running: export GROQ_API_KEY="..."
GROQ_API_KEY = os.environ.get("GROQ_API_KEY", "")
RELAY = OutputDevice(17, active_high=False, initial_value=False)

def pulse_door():
    RELAY.on()
    time.sleep(0.5)
    RELAY.off()

def decide_action(transcript):
    words = transcript.lower().strip()
    if "open" in words:
        return "open"
    if not GROQ_API_KEY:
        return "none"
    res = requests.post(
        "https://api.groq.com/openai/v1/chat/completions",
        headers={"Authorization": f"Bearer {GROQ_API_KEY}"},
        json={
            "model": "openai/gpt-oss-20b",
            "messages": [{"role": "user", "content": f"Door command: {transcript}"}],
            "max_tokens": 60,
        },
        timeout=8,
    )
    return "open" if res.ok and "open" in res.text.lower() else "none"

if __name__ == "__main__":
    if decide_action("Open the door please") == "open":
        pulse_door()
        print("Door relay pulsed.")

6. Limits of the Voice Lock (For the FYP Presentation)

Explain these three facts clearly to your FYP examiners:

  • Replay risk: A phone recording of the enrolled speaker can score above the threshold and unlock the demo door.
  • Similar voices: Family members or speakers with a close vocal pitch can occasionally pass a simple cosine similarity threshold.
  • Not a security lock: Real access control combines voice with a PIN, NFC badge, or physical deadbolt rather than relying on a browser voiceprint alone.
